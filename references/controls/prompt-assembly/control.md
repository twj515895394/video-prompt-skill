# Prompt Assembly Control

## 目标

把任务目标、素材职责、时间轴、主体运动、镜头、连续性、表演、音画、风格和限制组织成一份清楚、无重复、可直接执行的通用导演方案。

本页负责信息优先级、组装顺序、压缩、冲突裁决和输出完整性；具体模型语法由适配层完成。

对于 Action Combat，本页还必须保证：

> **State Machine Internalized, Choreography Externalized.**  
> **状态机内化，动作编排外显。**

内部状态可以复杂，但 Final Prompt 必须由正向、可见、可执行的动作语言主导。

---

## 何时读取

- 已经有大量设定，但最终 Prompt 冗长、重复或互相冲突；
- 用户给了剧情、镜头、风格、参考素材和限制，需要合成最终交付；
- 多镜头或多片段输出结构不统一；
- 正向描述和负向限制比例失衡；
- 复杂 Combat Prompt 被 Range / Advantage / Condition 等内部术语淹没；
- 需要把通用导演方案交给某个模型适配页进行最终转换。

---

## 信息优先级

```text
用户当前明确要求
→ 必须保留 / 必须修改 / 必须禁止
→ 当前任务 Playbook
→ 输入素材职责绑定
→ 时间轴与核心控制决策
→ 风格和详细资料
→ 自动补全
```

低优先级内容不得覆盖高优先级约束。

### Combat 语义优先级

Combat Final Prompt 的内部压缩优先级为：

```text
1. 正向可见 Action Phrase / 因果攻防 / Contact / Reaction
2. Position / Range / Environment 的可见变化
3. 动作速度、重量、Rhythm、Character Identity、Signature Moment 的可见表现
4. Camera / Audio 对可读性与冲击的支持
5. 少量真正必要的连续性与高风险 Negative Constraints
```

> **动作语言是主体，状态解释是内部工具。**

---

## 通用导演方案结构

```text
1. 任务与输出目标
2. 素材职责和保留边界
3. 全局稳定项
4. 场景、主体和初始状态
5. 绝对时间轴 / 镜头顺序（任务需要时）
6. 每段主体运动
7. 每段镜头状态
8. 表演和音画事件
9. 风格、光影和质感
10. 连续性与失败限制
11. 模型适配入口
```

并非每项都要作为独立标题展示，但最终 Prompt 必须覆盖当前任务真正需要的部分。

Combat 的内部 Combat Planning Context / State Contract 不作为默认展示块。

---

## 组装顺序

### 1. 先写任务核心

第一段就明确：

- 生成什么类型的视频；
- 时长或段落规模；
- 唯一主叙事 / 观看目标；
- 文生、图生、视频参考、编辑、延长或音频驱动等任务性质。

### 2. 再写参考关系

有素材时优先说明：

- 每份素材的职责；
- 人物、服装、场景、动作、运镜和声音分别由谁提供；
- 强保留和禁止继承项。

不要在后文反复重新解释素材职责。

### 3. 建立全局画面和稳定项

只保留跨全片真正稳定的内容：

- 人物身份；
- 场景骨架；
- 主服装和关键道具；
- 画面现实度或渲染方式；
- 主光源和色调；
- 必须贯穿的连续性要求。

动态变化放到时间轴 / 动作流，不把终态写成全局固定项。

### 4. 写时间轴或镜头单元

普通任务可使用统一顺序：

```text
时间 / 镜号 → 主体状态与动作 → 镜头状态 → 表演 / 声音 → 结束状态
```

同一信息只出现一次。若全局已锁定服装，不必每镜重复完整服装描述。

Combat 中，时间段不能因为机械秒点切断一条自然 Action Phrase；如果目标模型不需要精确时间戳，可以使用“立即、紧接着、在对方尚未恢复前、随后”等连续动作语言保持因果。

### 5. 补风格和质感

风格必须转成可执行变量：

- 拍摄来源；
- 观看位置；
- 景别与机位倾向；
- 光源、阴影和色调；
- 材质、环境和画面节奏。

风格不得覆盖主体动作和镜头任务。

### 6. 最后补限制

限制只针对当前高风险失败：

- 身份漂移；
- 动作跳跃；
- 镜头漂浮；
- 道具复制；
- 口型错误；
- 无关元素、文字或水印；
- 目标模型已知高风险项。

通常只保留少量高价值限制，而不是堆满通用负面词。

Combat 只有在正向动作语言无法充分降低风险时，才显式加入 Negative Constraint。

## Combat Final Prompt Assembly

### 1. Internal State → Visible Action

内部：

```text
Range: Close
Advantage: A slight advantage
B balance compromised
Contact: Solid
Tactical: Counter-to-Counter
```

不要直接写成 Final Prompt 状态表。

应转译为类似：

> A 继续压进短距离；B 偏开手臂立刻反击，A 提前截住反击线路，用一记短促攻击打断节奏，清楚接触让 B 半步失衡；B 借桌沿稳住身体，在重心尚未完全恢复前立即从侧面重新切入。

重点是：谁做什么、对手如何响应、哪里发生接触、受力 / 压力如何传播、空间如何改变、这个结果怎样制造下一拍。

### 2. Action Language Dominance Check

Combat Prompt 不设置固定百分比，但在语义上必须明显满足：

- Action Phrase / Reaction / Contact / Consequence 占主体；
- Continuity / State / Negative 只做支撑；
- Camera / Audio 不抢占动作主体；
- Meta 解释不能比真正动作更长。

如果一段 Combat Prompt 大部分文字都在解释“保持连续、符合物理、不要瞬移、状态为……”，而真正攻防只有几句，应判为组装失败。

### 3. Preserve Causality During Compression

压缩时优先删除：

1. 重复状态解释；
2. 重复的连续性提醒；
3. 装饰性形容词；
4. 重复 Negative；
5. 不改变战斗关系的次要动作。

最后才考虑缩减有效攻防。

必须保留：

- Attack → Response → Counter / Continuation 因果；
- Contact → Reaction → Consequence；
- 关键 Range / Position 变化；
- Signature Moment 前后的铺垫 / Payoff；
- Ending 的真实收束。

### 4. Positive-first Constraint Strategy

优先写正向执行事实：

- “他被撞到桌边后重心被迫向侧面偏移，下一拍必须借桌沿稳住”；

而不是泛化写：

- “不要无视物理”；
- “不要瞬移”；
- “不要动作不连贯”。

Negative 只在当前存在明确生成风险时保留。

禁止自行加入用户没有要求、剧情没有依据的限制，例如无来源的“no visible weapons”。

## 单片段组装骨架

```text
视频目标：
参考与强约束：
全局画面：
动作 / 时间流：
镜头与表演原则：
音画设计：
必要连续性与高风险限制：
```

Combat 中“动作 / 时间流”应是主体，不要求机械拆成每 1–2 秒一个独立小段。

## 多镜头 / 多片段组装骨架

```text
全片目标与统一锚点：
素材职责：
段落规划：

Segment 1：
- 段落目标
- 动作 / 镜头时间流
- 结尾交接状态

Segment 2：
- 从上一段什么状态开始
- 动作 / 镜头时间流
- 结尾交接状态

全片声音、风格与连续性：
适配层入口：
```

---

## 去重规则

- 全局稳定项只在开头写一次；
- 时间轴内只写本段变化；
- 不同时使用多个近义风格标签；
- 不在正向描述和负向限制里重复同一句；
- 不重复列出已经锁定的参考关系；
- 同一运镜只保留一个明确术语和路线；
- 同一情绪只保留可见表演过程，不再堆抽象同义词；
- Combat 不重复输出 Range / Advantage / Condition 标签与已经动作化表达的同一事实。

---

## 冲突检查

重点识别：

- 固定机位与大幅环绕同时存在；
- 深景深与背景完全虚化同时存在；
- 角色保持静止与完成复杂动作同时存在；
- 完全复刻首帧与彻底改变构图同时存在；
- 慢节奏长镜头与每秒多次切镜同时存在；
- 强保留服装与中途无原因换装；
- 无对白与精准口型要求同时存在；
- 写实纪实与无物理限制的漂浮运动同时存在；
- Combat High Coverage 与大段站立对峙 / 提前 Ending Pose 同时存在；
- 高 Exchange Depth 与高 Camera Complexity 在模型低承载场景同时满强度。

冲突时不并列输出两个互斥要求，应根据优先级裁决并删除 / 降级低优先项。

---

## 压缩原则

压缩不是删除关键条件，而是：

- 合并重复描述；
- 把固定内容提升为全局约束；
- 把长术语列表改为一个明确选择；
- 删除不影响结果的装饰词；
- 用结构化动作流代替散乱故事段落；
- 用素材职责表代替反复解释参考素材；
- Combat 优先删 Meta / 重复约束，再删低价值辅助动作，最后才缩减有效攻防。

> **Clarity Through Structure, Not Action Reduction.**

---

## 适配层交接规则

通用导演方案完成后，模型适配层只允许：

- 转换素材引用方式；
- 调整推荐的语言组织形式；
- 根据模型能力调整同一时间窗口复杂度、Camera Complexity 或 Phrase 序列化；
- 补充模型明确要求的参数、边界和限制；
- 调整图生视频中静态描述与运动描述的比例。

适配层不得重新改变已经锁定的：

- 剧情；
- 人物身份；
- 核心 Combat Intent；
- Active Combat Coverage 目标；
- 空间关系；
- 动作因果；
- 战斗结果。

如果模型执行能力较弱，优先降低 Camera / 同窗口复杂度、拆成多个无缝 Phrase，再考虑缩减次要动作；不能直接把“高手持续对决”变成“两三次简单交换”。

---

## 输出前完整性检查

### 必查

- 任务性质和主目标；
- 输入素材职责；
- 初始状态；
- 主体运动；
- 镜头状态；
- 时间 / 因果顺序；
- 收尾状态；
- 连续性限制。

### Combat 额外必查

- Final Prompt 是否由 Action Language 主导；
- Active Combat 是否被真正写满，而非状态解释写满；
- Action Phrase 因果是否保留；
- Contact → Reaction → Consequence 是否可见；
- Range / Position 变化是否动作化；
- Camera / Audio 是否只做支持；
- Negative 是否少而有针对性。

### 按需

- 表演和对白；
- 音效和 BGM；
- 多镜承接；
- 风格和光影；
- 模型适配入口。

---

## 常见失败与修复

### Prompt 很长但不可执行

修复：删除抽象修饰和 Meta 解释，恢复“主体动作 + 对手响应 + 接触 / 结果 + 镜头 + 时间 / 连续性落点”。

### 每段重复完整人物设定

修复：把身份、服装和场景提升为全局稳定项。

### 负向词多于正向目标

修复：先补正向动作和镜头逻辑，只保留最相关风险限制。

### Combat 状态表比动作更长

修复：保留内部 State，Final Prompt 改写成可见动作、受力、换位和后续机会。

### Combat 为了“清晰”只剩几次动作

修复：恢复 Action Sufficiency；用 Phrase 分层、降低 Camera Complexity 与去冗余获得清晰，不通过动作通缩获得清晰。

### 风格词互相竞争

修复：保留一个题材气质和一个设备 / 观看位置，其余删除。

### 模型语法污染通用层

修复：通用方案先独立完成，最后一步才进入模型适配。

---

## 输出前检查

- 信息优先级是否正确；
- 是否有互斥要求；
- 全局项与动态变化项是否分开；
- 是否存在大段重复；
- 正向描述是否足以独立成立；
- 负向限制是否针对当前风险；
- Combat 是否“状态机内化、动作编排外显”；
- 模型适配是否只改变表达方式和执行路径；
- 最终文本是否可以直接复制使用。
