# Cinematic Combat Camera Language

## 1. 定位

将动作戏按影视场面调度设计，而不是按比赛录像记录。镜头不是把每一招完整展示一遍，而是选择观众此刻最需要读取的动作信息：攻击意图、接触点、受力结果、位移、支撑变化、主动权变化和人物反应。

核心原则：

> **动作决定镜头为什么变化；镜头负责把动作后果变成观众能读到的电影信息。**

> **完整动作可读不等于全程固定全景；高信息密度应通过动作拆分、景别分工和动作匹配剪辑实现。**

> **需要慢的是关键接触、受力和失衡，不是整段攻防。**

该规范补充 `action-camera-handoff-playbook.md` 的语义 Gate，不替代 Combat State、Choreography、专项武术动作和最终 Prompt Assembly。

## 2. 先定义 Viewer Task，再选择景别

每个高价值镜头先回答：

```text
当前动作因果是什么？
观众此刻必须看清什么？
哪个角色 / 身体区域 / 空间关系承担这个因果？
动作完成后，下一镜要继承什么仍然活着的状态？
```

根据 Viewer Task 选择观察方式：

| 观看任务 | 优先观察方式 | 不要误用 |
|---|---|---|
| 交代双方位置、门口到庭院的路线、距离和主动权 | 短促中远景、低机位双人中景或跟拍 | 用长时间全景承载全部招式 |
| 单人发起攻击 | 发起者中近景、肩线/拳腿方向、带脚步的半身或中景 | 先把双方摆好再慢慢轮流出招 |
| 拳掌肘与防守接触 | 接触区域近景或足够容纳双方接触关系的中近景 | 只写“关键时刻切特写” |
| 受击、失衡、被迫移步、主动权变化 | 被击者单人反应、脚步/重心局部，必要时回到双人中景确认位置 | 只拍攻击者命中，不拍后果 |
| 蹬柱、低扫、正蹬、落地、跨越边界 | 能同时容纳髋部、支撑、路线和对手关系的低机位中景/中远景 | 把真实空间动作裁成孤立鞋部特写 |
| 倒地、喘息、画外威胁和剧情悬念 | 受击者中近景或上半身中景，保留视线方向和画外空间 | 重击后立刻恢复站立或重新双人站桩 |

景别只是观察容量，不是运镜。景别与镜头运动必须分别写：例如“低机位双人中景，横移跟随蓝衣追步”，而不是只写“全景打斗”。

## 3. 影视级打斗的镜头分工

一段高密度攻防应在以下几类观察方式之间自然切换；不要求每场都使用全部类型，也不把它们变成固定 Shot Template：

### 3.1 空间关系镜头

短暂建立双方起始位置、逃退路线、障碍物、轴线和战斗空间。只在空间状态真正变化时重新建立，不把它当成整段动作的默认视角。

### 3.2 发起者镜头

把攻击写成单人主动行为：脚底压地、胯部送入、肩线转动、拳掌沿哪条线进入。对手可以只露局部或只以反应出现，使攻击有主体性，而不是两人同时做对称动作。

### 3.3 接触点镜头

镜头落在拳、掌根、前臂、肘、腿与目标的真实接触区域。必须同时交代接触方向、受力瞬间和下一状态；接触点不是静态展示，也不能用镜头冲击或音效替代身体后果。

### 3.4 受击反应镜头

切到被击者的肩线、胸腔、头部、支撑脚或身体轴线变化，显示被迫偏转、补步、失衡、退让或重新架起防守。受击镜头应继承上一镜的接触和动量，而不是重新摆出反应姿势。

### 3.5 身法与路线镜头

当动作改变 Range、Level、Axis、Support 或 Fight-space 时，使用足以看清起点、借力点、路径、落点和下一状态的镜头。快速横移、低机位抬升、贴地跟拍和短促摇镜都必须服务于路线或高度变化。

### 3.6 结果与悬念镜头

重击后不要急着回到双方全景。先让受击者承担落地、喘息、护伤、撑地和视线恢复，再决定是否让优势方进入画面。若剧情需要画外压迫，允许优势方只以脚步、衣摆阴影、呼吸或视线方向存在。

## 4. 快节奏不是加速所有动作

高密度动作段落采用“短任务、活切点、连续动量”的方法：

- 一个镜头主要完成一个任务：起势、接触、偏转、追步、借力、落地、受击、恢复之一；不要在一个镜头里堆多个互相独立的完整主事件。
- 完整身体同框只在需要观众理解空间、脚步、借力、路线和落点时使用，并在动作仍有动量时切走。
- 单人攻击镜头、接触点镜头和受击反应镜头可以交替，让观众感到连续攻防，而不是轮流报招。
- 快切应发生在拳仍在前伸、前臂刚接触、脚步正在补位、身体正在旋转或受击者正在失衡时；下一镜继承仍活着的 Motion / Contact / Pressure / Support / Recovery。
- 不要等动作完成、人物站稳、双方重新摆架后再切；这种“动作完成 → 站稳 → 下一镜重新开始”属于 Dead-motion Cut / Kinetic Handoff Loss。
- 需要清楚的动作不一定要放慢；优先用更合适的景别、动作匹配剪辑和接触后果提高可读性。
- 只有高价值接触、身体受力、重心丢失、落地和关键剧情反应允许短暂降速或更长停留；攻防主体仍应保持即时推进。

节奏预算应服从片段时长和动作复杂度，不使用固定镜头数量、固定秒数或固定快切模板。若独立主事件超出时长，应提醒拆段或取舍，而不是把每个动作都压成不可读的碎切。

## 5. 动作匹配剪辑合同

可使用以下因果链，但必须根据当前动作选择，不机械套用：

```text
发起者脚底 / 肩胯启动
→ 攻击路线正在形成
→ 切到防守者前臂 / 身体角度
→ 接触仍在发生
→ 切到受击者重心 / 支撑脚后果
→ 下一动作继承偏转、被迫移步或未收完的攻击
```

镜间至少继承一类活跃运动状态，并在需要时继承空间状态：

```text
Motion State：Momentum / Contact / Pressure / Rotation / Support Transfer / Forced Step / Recovery
Spatial State：Position / Left-Right / Direction / Axis / Range / Level
```

切镜后不能让角色无因恢复到默认架势，也不能让上一镜的受击、失衡或攻击压力消失。若空间关系可能因局部近景丢失，在下一次高价值路线变化前用足够宽的 Re-establish 恢复位置，不要为了安全把全段锁成固定全景。

## 6. 电影化运镜规则

- 跟拍用于承接追步、退让、冲入和离开空间边界；必须有明确路线和停止/交接点。
- 横移或快速摇镜用于揭示接触、改变双方关系或跨越空间障碍，不用于装饰性晃动。
- 低机位用于放大支撑、腿法、落地、身法高度或压迫感；若局部无法同时解释双方受力，扩大到低机位双人中景。
- 推近或短促冲击用于高价值接触、临界失衡和人物主观压力；不要每次命中都推近。
- Reframe 由 Action State Change 触发：路线改变、主动权交接、Range 压缩/拉开、Level 改变、支撑转换、环境边界或受击后果。
- 避免机械循环 `Medium → Close-up → Medium → Close-up`；普通连接动作继续当前镜头，只有 Viewer Task 或 Action State 真正改变时才切换观察方式。
- 不同时堆叠多个主运镜；同一镜头明确主任务、起始状态、主运动、路线、速度和停点。
- 用户明确 One-take / No Cut / Fixed Camera 时，转为连续摄影内的 Reframe、距离、Height、Relationship 和跟随变化，不用剪辑规避硬约束。

## 7. 局部特写的因果门槛

当镜头收窄到拳、掌、肘、腿、脚、衣袖或受击部位时，被框住的局部必须在镜头持续期间真实承担当前 Combat Cause / Response / Consequence。

局部镜头必须至少回答一个问题：

- 它正在发力吗？
- 它正在接触或被接触吗？
- 它正在改变支撑、重心、路线或防守吗？
- 它正在显示受力后的持续后果吗？

如果真正的因果需要同时看见双方髋部、脚步、接触和空间关系，则使用中近景、低机位双人中景或更宽的 Reframe；不要用狭窄特写同时要求观众看清相距很远的多个身体区域。

判定失败：

```text
镜头切到局部
→ 局部没有承担当前因果
→ 真正攻防在画外继续
→ 特写只剩静态展示或装饰性运动
```

失败时扩大景别或继续当前镜头，不要为了保留特写而额外发明动作。

## 8. 战斗镜头设计的 Prompt 写法

不要只写：

```text
两人快速打斗，关键时刻切近景，电影感强。
```

应写成动作与镜头绑定的可执行句：

```text
蓝衣从已经伸出的手臂直接压地出拳；镜头先跟蓝衣肩胯和拳路，拳仍在前伸时切到红衣前臂斜架，接触没有停止；再切红衣支撑脚被迫横移和胸肩偏转，蓝衣沿同一方向追步进入下一掌。两人完整同框只保留跨越门槛和落地的短暂关系镜头。
```

最终导演版至少应同时写清：

- 起始空间与屏幕方向；
- 谁发起、谁反应、谁改变下一状态；
- 每个高价值动作的 Camera Anchor；
- 景别与运镜各自承担什么任务；
- 切镜发生在什么仍活着的运动状态；
- 接触后果如何进入下一镜；
- 片尾人物、视线、空间和声音落点。

## 9. Final Preflight：影视化打斗专项检查

交付前检查：

1. 是否把打斗写成了比赛记录，而不是场面调度？
2. 是否存在长时间双人固定全景、站桩轮流出招或“你打一招我打一招”？
3. 每个关键切镜是否有具体 Action Anchor、Viewer Task 和 Live-motion Handoff？
4. 单人起手、接触点、受击后果和空间路线是否分工清楚？
5. 是否在真正需要时才使用完整身体同框，而不是因“可读”锁死全程大景别？
6. 需要慢的是否只是接触、受力、失衡和落地，而不是整段攻防？
7. 局部特写是否真的承担动作因果？
8. 切镜后是否继承方向、轴线、距离、支撑、受力和身体姿态？
9. 是否有明确结束状态，而不是重击后突然恢复或重新摆架？

任一项失败：回到 Action–Camera Handoff、Viewer Task、Framing Capacity 或 Prompt Assembly 对应层修正；不要只增加“电影感、快速剪辑、冲击特写”等空泛词。
